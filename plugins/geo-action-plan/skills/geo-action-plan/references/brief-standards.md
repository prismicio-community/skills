# Brief standards

Read this while writing Step 5's briefs. A brief passes when a writer could start without booking a meeting.

## The universal bar

Every brief carries four things:

1. **The angle** — the specific differentiator, named concretely, verified against incumbent content actually read.
2. **The structure** — the H2s, what tables or schema to include, and target length only where it matters.
3. **The dependency** — which brand asset the angle needs, and an explicit flag when the brand does not have it. A flag is not a resolution: if the asset is missing, the plan must also carry an executable row covering the same intent (see "The evidence ladder" in `plan-methodology.md`). Say which row is the prerequisite for which.
4. **The honesty instruction** — where competitors get named fairly, where limitations get stated, and where the "when you don't need us" section goes.

## Per-page-type templates

**Listicle**
Entry count and how entries were chosen; the categorization scheme that beats a flat list; per-entry structure (what it is, who it suits, pricing reality, honest limitation); where the brand appears and why that placement is defensible; the methodology paragraph, if there is real testing behind it. Listicles that rank the brand first without justification get skipped by assistants and readers alike — place it where it belongs and say why.

**Comparison (brand vs competitor)**
The feature table's actual rows; the dimensions that matter for the query's phrasing, not the ones that flatter the brand; a required "when [competitor] is the better fit" section; pricing with real numbers or an explicit note that pricing is quote-based.

**Comparison (neutral X vs Y)**
Only plan this when the brand can credibly referee — it must not be a competitor of both. State the refereeing basis in the intro. The brand appears once, at the end, as a disclosed alternative.

**Product / capability page**
The capability phrasing verbatim from the query; what the product does in the first 60 words in extractable prose; the concrete mechanism, not the benefit adjective; one real screenshot or code sample; the honest boundary of what it does not do.

**How-to guide**
The task's actual steps; where it names tools, name several including competitors; the prerequisite section; the failure modes.

**Alternatives page**
Which product's alternatives; entry structure identical to the listicle template; the brand's own entry written as if by a neutral party.

**Evidence asset — original testing (rung 3)**
The claim it proves; the numbers required from the brand, named explicitly and left blank in the draft until they exist; the methodology section, stated plainly enough to be repeated; the raw data table, because tables get extracted. If a rung-1 synthesis is planned for the same intent, this brief states that it must not go to a writer until that row has shipped, and why: the synthesis determines what is worth measuring.

**Evidence asset — cross-case synthesis (rung 1)**
The corpus, listed by source with what each one concluded; the comparison structure (what varies, what holds, what predicts the difference); the survivorship section built from reversals and unanswered questions in the same dataset; per-source attribution for every figure in the comparison table; a closing section naming what the brand would test next, which hands off to the rung-3 row. State in the brief that the value is the comparison and that a sequence of summaries adds nothing — this is the instruction that erodes first under deadline.

## Update briefs are diffs

An Update or Retarget brief is written against the fetched current page, in three parts:

- **Keep** — the sections that already work, named.
- **Change** — the specific sections and what is wrong with them.
- **Add** — the sections the incumbents have that this page lacks.

A brief that could apply to any page on the topic was not written against the real page. Read the page and rewrite it.

## Extraction-optimized writing

Applies to every brief regardless of type:

- Self-contained quotable sentences — a claim that makes sense lifted out of its paragraph.
- Question-led H2s matching the phrasings in the fan-out queries.
- Answers in the delivered HTML, never behind JS accordions.
- Visible publication and update dates.
- FAQ answers in the page body, not only in schema markup.

## What a brief may never contain

- A statistic the brand did not supply. Briefs request numbers; they do not invent them.
- A claim about a competitor that was not verified against their page.
- "Write a better version of X" as the angle.
- A word count as the primary instruction.
- An assumed customer quote, case study, or test result.
